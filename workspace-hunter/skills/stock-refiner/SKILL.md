# Skill: stock-refiner（低吸粗筛·AI精选）

## 用途
读取 `stock_push.py`（低吸单季盈利策略）筛选出的在池股票，由AI进行三层精选：
**① 股票类型判定（只留成长股，剔除周期/价值/其他）→ ② 最新财报精读评分 → ③ 未来盈利方向评估**，
最终将入选与全部剔除理由推送到飞书。手动触发（用户说"跑一次精选"之类）。

## 输入文件
`/home/admin/Hualin/quant_hits_detail.json`（由 stock_push.py 每次 cron 运行生成/覆盖）

## 执行流程（严格按序）

### Step 0：获取数据
```bash
# 检查JSON新鲜度（2天内=fresh）
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/ensure_json.py
```
- `status=fresh` → 直接读 `/home/admin/Hualin/quant_hits_detail.json` 进入 Step 1
- `status=stale/missing/corrupt` → 告知用户"需重跑主程序（约45-60分钟，会同时推送企业微信）"，获用户知情后：
```bash
# 阻塞运行至完成（用 exec 长超时或 background）
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/ensure_json.py --run
```
- 若 `hits` 为空数组且 `run_info.is_final=true` → 空池：推送"今日无在池股票"即完成（无剔除理由可写）

### Step 1：缓存判断（省搜索配额）
缓存文件：`~/.openclaw/workspace-hunter/skills/stock-refiner/data/refine_cache.json`
- 计算 `quant_hits_detail.json` 的 `hits` 部分内容 md5；与缓存中上次 md5 一致且分析时间≤2天 → 直接复用上次结论，仅重发报告
- 不一致/无缓存 → 全量分析

### Step 2：股票类型判定（每股，先脚本后AI）
```bash
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/fetch_features.py 002192.SZ 600519.SH ...
```
按 `references/scoring_rules.md` 第一节执行三层判定（量化特征 × `references/industry_map.json` × 价格驱动核验）：
- 周期嫌疑≥2条 → 剔除（记录证据）
- 每股最多2次定向搜索验证（如"公司名 主营产品 价格"），tavily配额尽则降级exa
- 产出：每只股票的类型（成长/周期/价值/其他）+置信度+依据
- **只保留成长股进入 Step 3**；若全部被剔 → 跳到 Step 5 输出全排除报告

### Step 3：最新财报获取与精读（仅成长股）
```bash
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/fetch_latest_report.py 002192.SZ --download
```
- **新鲜度校验（铁律）**：`tushare_latest.ann_age_days <= 153`（5个月）；且对照锚点表：
  当月应见到的最新报告期：1-4月→上年年报(Q4)、4-5月→一季报Q1(或上年年报)、7-8月→中报Q2(或一季报)、10-11月→三季报Q3(或中报)。落后锚点2个季度以上 → 报告中标注"披露滞后"并降置信度
- **必须用 pdf 工具直接精读下载的官方PDF**（`data/report_pdfs/*.pdf`，来源东方财富公告库），不许只依赖二手解读文章：
  1. 先读目录/前几页定位"管理层讨论与分析/经营情况讨论"章节，精读
  2. 资产负债表关键科目：合同负债/预收款、在建工程、存货、应收（对比上年末）
  3. 搜"展望/预计/产能/订单/在手"关键词定位前瞻段落
- 若PDF下载失败：退而求其次用 tushare 结构化数据 + 搜索近30天财报解读（标注"未读原文"降置信度）

### Step 4：财务评分 + 未来方向 + 四面评估
按 `references/scoring_rules.md` 第二、三节逐股执行：
- 财务5维评分（0-10，≥7通过）；红旗两项 → 一票否决
- 方向评估：L1（财报原文前瞻+领先指标）> L2（券商EPS修正方向，搜索）> L3（行业景气，搜索）
- 每股搜索预算：L2+L3合计≤3次
- 结论必须挂具体数字+来源，搜不到写"未获取"，**严禁编造**

**Step 4b：四面评估（2026-08-20新增，规则见 scoring_rules.md 第五节）**

**4b-1 技术+资金面（全池股，脚本，零搜索配额）：**
```bash
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/fetch_technical.py <全部在池代码空格分隔>
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/fetch_capital.py <全部在池代码空格分隔>
python3.11 ~/.openclaw/workspace-hunter/skills/stock-refiner/scripts/fetch_news_signals.py <全部在池代码空格分隔>  # 公告分类+事件日历(免费)
```
- 输出已含0-10评分与支撑压力位；异常值（如股东户数数据期过旧）需AI复核
- 定位：技术/资金面管**择时**，不否决选股
- **股东户数优选（老板要求 2026-08-20）**：fetch_capital.py 已输出最近5期户数趋势（连续下降期数/累计变化）。多只入选时**户数下降趋势者优先排序**（户数下降=筹码集中）；报告资金面行必须展示户数趋势序列，不得只给最新一期

**4b-2 消息+政策面（仅成长股，搜索）：**
- 消息面：以 fetch_news_signals.py 公告分类+事件日历为底 → AI复核边界案例 + 舆情搜索≤2次/股（关键词："{公司名} 利空/诉讼/减持/处罚 近30天"）
- 政策面：搜索≤2次/股（"{行业} 政策/规划/补贴 2026"）；**出口型必查贸易政策**（industry_map.json trade_sensitive 池命中 或 财报海外营收>30%）
- **消息面硬否决：立案调查/业绩暴雷(预减>50%或首亏)/审计非标 → 直接出局（报告注明）**
- **消息新鲜度铁律：每条消息必带日期，>7天默认已消化**
- 成长股每股总搜索预算：≤9次（含Step 2/4已用）

用 message 工具（channel=feishu）推送，格式：


推送后将结论写入 `data/refine_cache.json`（含hits-md5、时间、逐股结论）。

## 铁律
1. **不编造**：任何数字/结论必须可溯源（脚本输出/PDF原文/搜索结果），没有就写"未获取"
2. **财报必须最新**：Step 3 新鲜度校验不过的，报告中醒目标注，不得当作有效前瞻证据
3. **剔除也要说清理由**：空精选报告同样完整（用户明确要求）
4. 搜索预算：每股全流程≤5次；**成长股（进Step 3的）放宽到≤9次**（tavily→exa降级）；超8只在池时先用类型判定砍到≤8只
5. 主程序推送企微是接受的副作用，无需请示；但**调起主程序前要先告知用户耗时**
6. python3.11 运行本skill脚本；主程序用 /home/admin/financial/bin/python（3.6）
7. **消息面硬否决**（立案/暴雷预减>50%/审计非标）→ 直接出局，报告注明
8. **每条消息/政策必带日期**，>7天的催化剂默认已消化，不得当作近期催化
9. **禁止臆想（2026-08-20老板要求）**：所有事实性陈述（公司事件/价格/政策/券商观点/行业数据）必须溯源到脚本输出、财报PDF原文、公告原文或搜索命中。**AI自身记忆不得作为事实来源**，只能作"待验证线索"——必须先搜索验证、拿到带日期的来源后才能引用。搜索无果就写"未发现"，严禁用"印象中/应该"填充。引用搜索结果时不得脑补结果里没有的细节
10. **信息时效标准（2026-08-20老板要求）**：每条信息必带日期，过期信息按下表降级或禁用：

| 信息类型 | 有效期 | 超期处理 |
|---------|--------|---------|
| 行情/技术面/资金面 | 最近收盘日 | 标注"截至YYYY-MM-DD收盘"；隔周末注意区分 |
| 消息/公告催化 | 7天内=新鲜 | >7天标"已消化"；消息面只统计近30天 |
| 券商观点(L2) | 90天内 | >90天不得作方向证据，只能作背景并标注日期 |
| 政策 | 12个月内=现行 | >12个月标"存量政策(现行有效)"；只有近90天新政策算边际催化 |
| 行业数据(L3) | 90天内 | >90天降级为背景参考，标日期 |
| 财报数据 | 最新报告期 | 引用必带"XX报告期"，旧报告数据与新报告冲突时以新为准 |
